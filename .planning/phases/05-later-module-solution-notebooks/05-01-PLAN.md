  <behavior>
    - Test 1: `change_score(a, a)` (identical row-aligned matrices) returns an all-zeros array, shape `(n,)`, dtype float32 — identical embeddings mean zero change.
    - Test 2: two orthogonal unit rows (`a[0] = [1,0,...]`, `b[0] = [0,1,...]`) give `change_score` value `1.0` for that row (1 - cosine(a,b) = 1 - 0).
    - Test 3: two opposite unit rows give value `2.0` (1 - (-1)).
    - Test 4: shape mismatch (`a.shape != b.shape`) raises `ValueError` naming both shapes in the message (mirror `cosine_similarity_map`'s existing mismatch-message style).
    - Test 5: matches a naive per-row loop computation (`1 - row_a @ row_b / (norm_a * norm_b)`) within `atol=1e-5` on random non-unit-norm data, proving the function does not assume its inputs are already unit-norm (same guarantee `cosine_similarity_map` documents).
  </behavior>
  <action>Add `change_score(a: np.ndarray, b: np.ndarray) -> np.ndarray` to course/embeddings.py, placed after `cosine_similarity_map`. Both `a` and `b` have shape `(n, d)`, band-last (the same orientation `cosine_similarity_map`'s `matrix` argument uses — the orientation a frozen table's `to_matrix()` output and a `course.data.load()` GeoDataFrame's embedding columns come out in). Add a docstring stating this is the paired, row-aligned counterpart to `cosine_similarity_map`'s query-vs-matrix broadcast, intended for "same point, two years" change detection (Module 4) — do NOT loop `cosine_similarity_map` per row to build this; it is a distinct einsum contraction.</action>
