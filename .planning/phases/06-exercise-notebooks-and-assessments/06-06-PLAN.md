<interfaces>
From 06-01's `tools/derive_exercise.py` (already implemented): `transform(nb, appendix=None,
slug="")` handles `task`/`hidden` tags, BEGIN/END SOLUTION markers, and appendix Reflection/Stretch
cell injection. This plan adds one more transformation step to `transform`, applied after stub
replacement and before appendix injection: for every whole-cell-replaced `task` cell (not a
marker-based partial replacement — those keep enough surrounding code that the "spoiler" is
already partially visible so no separate link is warranted), insert immediately after the stub
cell one new markdown cell:

```
<details>
<summary>Show solution</summary>

See <code>notebooks/solutions/{slug}.ipynb</code> — the same section, just above this point in
the notebook.
</details>
```

`<details>`/`<summary>` render collapsed by default in both JupyterLab's markdown renderer and
Colab/nbviewer, satisfying "never spoiled by running all cells" (EXER-04) since nothing executes
and nothing is visible until the reader clicks. Do not paste the original solution source into
the markdown — a bare pointer to the solution notebook only, per FEATURES.md's "or link to the
solution notebook" alternative (simpler than embedding code, avoids any duplication-drift risk).

nbstripout awareness for regeneration testing: `nbstripout` strips cell `outputs` and execution
`count` on commit, so the *committed* exercise `.ipynb` files never carry outputs. The
regeneration test must therefore compare the freshly regenerated notebook against the committed
one only after stripping outputs from the freshly generated copy too (or by comparing only `cells[
].source` + `cells[].metadata.tags`, ignoring `outputs`/`execution_count`), or it will fail
spuriously on any notebook that still has stale execution metadata in memory.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| generator output -> committed exercise notebooks | A generator bug could silently corrupt an exercise notebook or leak solution code past the intended stub boundary |
| solution-link cell -> spoiler risk | If the link cell ever embedded solution source instead of a bare path reference, "running all cells" would still not spoil it (markdown isn't executed) but a rendering bug could show it unconditionally instead of collapsed |
