<objective>
Build and unit-test the exercise-notebook generator: a script that reads a tagged solution
notebook and writes a derived exercise notebook, replacing task cells with stubs and dropping
hidden cells, while leaving everything else — markdown, checkpoint asserts, wrong-conclusion
traps, parameter knobs, setup/data cells — untouched.

Purpose: EXER-01 requires this generator to exist and be unit-tested *before* it is run against
the seven solution notebooks (planned in 06-06). The generator is the deliverable that prevents
exercises from drifting from their solutions.
Output: `tools/derive_exercise.py`, `tools/exercise_appendix.yaml` (per-notebook reflection/stretch
content schema), `tests/test_derive_exercise.py`, a tiny fixture notebook for the tests.
</objective>

<interfaces>
Tag vocabulary this plan defines (no existing generator or vocabulary exists yet — the
notebooks' current `solution` tag was applied for an unrelated purpose in earlier phases and is
NOT the exercise-derivation vocabulary; ignore it, do not treat it as input):

- `task` — this cell's code becomes a stub in the exercise notebook. If the cell source contains
  the literal lines `### BEGIN SOLUTION` and `### END SOLUTION` (each on its own line), only the
  text between them (inclusive) is replaced; everything outside those markers in the same cell is
  kept verbatim. If no markers are present, the entire cell source is replaced.
  Stub template (whole-cell case): a `# TODO: ` comment line synthesized from the nearest
  preceding markdown heading/paragraph text (fall back to `# TODO: implement this cell` if none
  found), followed by `raise NotImplementedError("Implement this cell — see the module's solution
  notebook if you get stuck.")`.
  Stub template (marker case): replace only the marked span with the same two lines, keep
  pre/post-marker code from the original cell intact.
- `hidden` — cell is dropped entirely from the exercise notebook (not converted, not stubbed).
  Reserved for future checker self-tests (EXER-06, v2, out of scope here); expect zero uses in the
  seven v1 notebooks, but the generator must support the tag.
- All other tags (`checkpoint`, `wrong-conclusion`, `parameters`, `skip-execution`, `setup`, no
  tag) and all markdown cells pass through byte-identical.

`tools/exercise_appendix.yaml` schema (new file, keyed by notebook slug e.g. `02_similarity_and_classification`):
```
<notebook-slug>:
  reflection:
    - "<question text>"
  stretch:
    - "<task text>"
```
The generator reads this file and, if a matching key exists, appends one markdown cell titled
`## Reflection` (bullet list of `reflection` items) and one titled `## Stretch tasks` (bullet list
of `stretch` items) at the end of the notebook, after the last existing cell. If no key matches
the notebook slug (derived from the input filename stem), the generator emits a UserWarning and
skips appendix injection — do not fail the run.

CLI contract (argparse): `derive_exercise.py <solution_path> <exercise_path> [--appendix PATH]`.
`--appendix` defaults to `tools/exercise_appendix.yaml` relative to CWD. Exit code 0 on success,
non-zero with a message to stderr if the solution notebook fails `nbformat.validate` after
transformation.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| generator input -> generator output | The generator reads and rewrites notebook files; a bug could silently corrupt or truncate a solution notebook if run in-place |
| appendix YAML -> notebook content | `yaml.safe_load` only (never `yaml.load` unsafe) — the appendix file is author-controlled but the habit matters |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | tools/derive_exercise.py | mitigate | Generator never writes to the solution notebook path — CLI requires distinct `solution_path`/`exercise_path` args; add an assertion that the two resolved paths differ before writing |
| T-06-02 | Information Disclosure | hidden-tagged cells | mitigate | `hidden` cells are dropped from the output notebook object before serialization, never written to disk in the exercise file |
| T-06-03 | Tampering | exercise_appendix.yaml parsing | accept | `yaml.safe_load` used exclusively; file is author-authored and version-controlled, no untrusted input path |
</threat_model>
